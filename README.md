DataHandler: This server script handles data saving and leveling up using the Roblox API service "DataStoreService", which is the built in method in the engine to save a player's progress. It creates the player's core values on join in a folder that is a child of the player object, and overwrites those values with the player's values on their last session if they had existing data.
DamageModule: This is a ModuleScript, which is a type of lua script that can be called so that it's functions can be called from external scripts. This is a very efficient way of code management that doesn't require us to copy paste the same logic onto every script that needs that system/function. In this case, it handles the dealing of damage, and although it can easily be done in a few lines in another script, unifying it into a single modular function made it so that we didn't have to change the logic for every singe place where a player or an enemy has to take damage when we later added attacker and victim separation via an objectvalue called "creator" to make the giving of rewards on defeating an enemy functional.
LevelGuiClient: This is a LocalScript or a Client Script, which is used to handle logic on the client's side. GUI can only be controlled through the client on most occasions, so this one reads the level and exp values from the player object and updates the exp bar and its text according to those values.
HitboxModule: This is also a modulescript, and it is used as a way of detecting if the attacker's blow landed on the victim or not. Calling .Touched on the weapon object is generally an unreliable source of hit detection and makes the combat feel very clunky, so we spawn a non-collidable but touchable part that determines the attack's reach. When a hitbox detects an victim hit by the attack, it returns the victim object to the attack script so that it can deal the damage or whatever effect the hitbox has.
WeaponScript: This is the server script for the base weapon, using HitboxModule and DamageModule to deal damage on tool use / click (Weapons are generally made as a tool object for simplicity), and also deal slight knockback to help keep distance by adding a velocity object to the target to the opposite direction. Also includes debounce so the attack can't be spammed. The damage and cooldown and attack animations are stored inside the tool object.
ArmorModule: This module stores the armor data and the beneficial stat boosts they provide, as well has handle the equip and unequip.
ArmorScript: This script is the server script for the actual armor equipping tool. This is a universal script that can be put into any armor tool as long as the tool's child stringvalue "ArmorName" is a valid name of an armor in ArmorModule's Dictionary. It sends the signal to equip/unequip the armor to the player.
